# Test plan: feature/back-in-stock

## Summary

Adds back-in-stock email sign-up (`POST /api/plants/{plantId}/notify`) and UI: a low-stock `StockBadge` on plant cards, and a `NotifyForm` on out-of-stock plant pages (via plant-card and plant-page slots). Behaviour is defined in `docs/features/back-in-stock.md` (product/docs win over code). Email collection is privacy-sensitive; money and sign-in are not in this diff.

## Notes for approval

- Docs/PRODUCT win over implementation and over the “no testing needed” comment in `api/src/features/back-in-stock.ts`.
- OpenAPI lists `409 already_subscribed` and full-email rules; feature doc requires case-insensitive one sign-up per email per plant and refusal of `a@b` / `name@` — API cases above follow the docs/contract, not the current Zod `includes('@')` check alone.
- Badge placement: doc says with tags under the name, never over photo/save; CSS on `StockBadge` is absolute — layout case in row 4 is intentional.
- Assumed — ask: exact API error payload/message strings for invalid email and `already_subscribed` beyond the UI string “You're already on the list”; whether duplicate check is global or per process after `onReset`.

Stop for approval before handing rows to specialists.
