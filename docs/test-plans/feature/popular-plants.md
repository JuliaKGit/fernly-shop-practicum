# Test plan: feature/popular-plants

## Summary

Adds **Popular right now** on every plant page: a new `GET /api/popular` endpoint ranks plants by units sold in the last 30 days; `PopularList` renders up to four links with units sold; a plant-page slot loads the list (requesting `limit=5`) and leaves out the plant on screen. Covered by `docs/features/popular-plants.md` (and OpenAPI text for the new path). No cart, checkout, money, privacy, or sign-in surfaces changed — those rows are omitted.

## Assumed — ask

1. **Performance harness:** popular-plants.md requires ~20 concurrent shoppers and p95 ≤ 300 ms for `/api/popular` and `/api/plants`. No existing load-test layout in the repo — confirm tool, duration, and whether this runs in CI or once manually (PP-02).
2. **“Sold this month” vs 30 days:** UI copy says “sold this month” while ranking uses the last 30 days. Confirm that wording is intentional (not a defect).
3. **Shared React Query key `['popular']`:** cache is not keyed by plant id (only the client filters `currentId`). Confirm stale/shared cache across plant navigations is acceptable; docs do not specify caching.

Stop here for approval before handing rows to specialists or writing tests.
